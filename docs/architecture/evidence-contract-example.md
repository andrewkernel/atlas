# Reviewable evidence-contract illustration

The [machine-readable illustration](../../configs/evidence-contract-illustration.json) is a proposed specification, not an implemented policy, schema-validated production record or executed Atlas verdict. Its strings naming future calibration obligations are deliberate descriptive fields; they are not executable numerical tolerances. A production schema must require typed finite numerical values and resolved artifact identities before execution.

The illustration gathers obligations exposed by the research into one reviewable contract. It grants no new optimizer/verifier capability. Reuse existing capture/comparison code where its actual relation matches, or supply an explicit adapter and positive/negative boundary controls. Never label a reused predicate with a different formula merely because its tolerance arguments have the same numbers.

## Decision walkthroughs

| Required observation | Corresponding evidence | Permissible report consequence |
|---|---|---|
|Both state values are equal infinities, but this parameter field requires finite health|[Comparison-policy fixture](../research/experiments/comparator-contract-control.md)|Equality may pass; health fails. A required health failure prevents numerical acceptance. Legitimate mask infinities require their own field policy.|
|Planner reports a 32 MiB managed schedule while requested budget is whole allocated memory|[Planner accounting control](../research/experiments/rockmate-compatibility.md)|Report both scopes. A schedule-budget pass cannot satisfy a differently scoped budget; use observed complete-update allocation where available.|
|A streaming target passes while a deferred verifier raises a shape exception|[Shared-stack controls](../research/experiments/interop-controls.md)|Record the verifier ERROR and differing execution relation. It neither accepts an unsafe plan nor establishes that the supported target execution is invalid.|
|Pure update parity matches but preparation advances RNG|[Constructor control](../research/experiments/rockmate-state-control.md)|A separate scientific-start precondition must be checked after preparation. Existing scoped RNG restoration has only its observed repair scope.|
|Five epochs complete with small three-pair validation differences|[CNN pilot](../research/experiments/fashion-pilot.md)|Report observations and pilot uncertainty. Numerical observations and replay do not establish outcome equivalence or a preserved domain conclusion.|
|Gross-board power integration and counter energy disagree|[Telemetry controls](../research/experiments/board-energy-control.md)|Retain both values/windows. Report unresolved accuracy/attribution; do not replace one endpoint with a favorable one.|
|A requested full reference cannot run locally|Proposed missing-reference case; not an additional executed experiment|Accept a scoped trusted external reference only under declared provenance/compatibility, or abstain on unobserved differential claims. Feasible candidate completion alone remains reportable.|

These are walkthroughs tied to actual finite observations or explicitly proposed cases; the table does not retroactively change any raw experiment's comparison convention. The report can contain PASS, FAIL, ABSTAIN and ERROR for different properties. It must not average them into a scientific score or collapse a numerical PASS into an overall conclusion.

## Production acceptance boundary

The first profiler slice should implement typed measurements and immutable identities before optimizing anything. Before a future decision can be emitted, every required property needs its exact predicate, scope, implementation version, evidence ID and outcome; its evidence ID must resolve to immutable bytes. Reference health and missing observations are separate from equality. Changed method fields require a newly approved scientific contract, not increased numerical tolerance.

An example contract is engineering infrastructure, not proof of research novelty. The [held-out selection comparison](../research/evaluation-estimands.md) still governs expansion. No frontend, API server, LLM, arbitrary project loader or generic verifier is implemented by this illustration.
