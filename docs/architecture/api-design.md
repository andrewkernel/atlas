# API and data contracts — proposed v0

Build the command-line/core path first. Later expose it with FastAPI and Pydantic v2-compatible models; resolve and test concrete versions when introduced. [Pydantic models](https://docs.pydantic.dev/latest/concepts/models/) provide data validation, not correctness of the scientific claims. Unknown fields, unsupported versions, nonfinite numbers and inconsistent counts must be rejected.

## Resource endpoints

All paths are under `/v1`; default loopback only. A local per-install token is required for mutating calls, with explicit origin/host policy. Use registered workload IDs; no uploaded Python, arbitrary import paths or shell command strings. Long jobs return202 and run in supervised workers.

| Method / path | Request | Response / semantics |
|---|---|---|
| POST `/experiments` | Adapter ID, config, contract, data manifest ID |201 immutable experiment ID and hashes |
| GET `/experiments/{id}` | — |200 spec, current evidence and supported capabilities |
| POST `/experiments/{id}/analysis` | Analysis options |202 job ID; static inspection only |
| POST `/experiments/{id}/profiles` | Profile windows, budget, execution policy acknowledgment ID |202 job ID, or409 approval/eligibility conflict |
| POST `/experiments/{id}/plans` | Profile ID, allowed strategy IDs, search budget |200 finite candidate set and exclusions; no execution |
| POST `/runs` | Experiment/plan IDs, budget, approval record ID where required, idempotency key |202 run ID; approval cannot be a caller-supplied boolean |
| GET `/runs/{id}` | — |200 state, exit reason, measurement availability |
| POST `/runs/{id}/cancel` | Reason |202/200 idempotent cancellation; never targets an arbitrary PID |
| POST `/verifications` | Reference/candidate run IDs, immutable check protocol ID |202/200 evidence; short checks and complete-training analysis named separately |
| GET `/reports/{id}` | JSON or Markdown representation |200 read-only report with artifact references |
| GET `/capabilities` | — |200 CPU/CUDA/telemetry/runner support and validated environment status |

Use 404 for unknown IDs,409 for immutable-state conflicts or duplicate incompatible idempotency requests,422 for invalid schemas, and 503 for unavailable device/model capacity. Preserve resource OOM as a terminal run reason, not merely a generic HTTP500. API error payload: code, message, safe details, retryability, related run ID; omit raw secrets/tracebacks.

## Minimum schema fields

| Object | Required fields |
|---|---|
| ExperimentSpec | schema_version, adapter_id/version, source_identity, config, data_manifest_id, initialization_recipe, seed_map, contract_id/hash |
| ScientificContract | schema_version, invariant_fields, allowed_strategies, allowed_method_changes, required_checks, numerical_comparisons, statistical_protocol_id or null, conclusion_review_required |
| ResourceBudget | device identifier, target allocated/reserved budgets with semantics, host RSS soft/hard mode, wall timeout, trial cap, output/disk/log caps |
| Plan | strategy versions and ordered parameters, source/config diff, precondition outcomes, affected dimensions, required checks, hash |
| CheckResult | property/version, dimension, outcome, evidence_status, scope, assumptions, evidence IDs, comparison protocol, limitations |
| Measurement | name, value or null, unit, observed window, source, support/error reason, sampling description |
| Approval | immutable execution-record hash, approved identity/time, policy version; generated by trusted local approval flow |

Telemetry validation rejects unsupported/sentinel readings rather than treating formatted OOM text as a measurement. The [Windows allocator-cap control](../research/experiments/cuda-budget-probe.md) observed impossible process-memory diagnostics. Keep allocator, reserved and device-wide measurements separately typed; a failed trial can still have valid partial allocator evidence.

### Illustrative property result

```json
{
  "schema_version": "1.0",
  "property": "buffers_equal_after_logical_update",
  "dimension": "numerical",
  "outcome": "FAIL",
  "evidence_status": "known_incompatible",
  "scope": "one controlled CPU update; specified input and environment",
  "assumptions": ["reference initialization replayed"],
  "evidence_ids": ["candidate-buffer-diff"],
  "comparison": {"kind": "exact"},
  "limitations": ["does not establish full-training outcome effect"]
}
```

This is an illustrative schema instance, not a real API response. Production evidence IDs must resolve to hashed artifacts. Do not mix an exact comparison label with a tolerance-based result. Statistical tests require named outcome, direction, margin, alpha, planned sample count and multiplicity policy; empty fields cannot default to a universal accuracy tolerance.

## Reproducibility and concurrency

Default one active GPU worker. SQLite stores durable queue/state with transactional transitions; worker handles are never API-controlled. The CLI and service call the same core functions so transport does not change semantics. Requests cannot mutate a running contract; changing a margin or invariant creates a new revision. The report preserves previous failures even after a human chooses a modified methodology.
