# Bibliography availability and metadata audit

The [read-only audit](../../benchmarks/audit_primary_bibliography.py) checked the first primary link in each of 32 paper notes. [Captured results](bibliography-availability-audit.json) retain retrieval time, note identity, resolved URL/status, title and available HTML citation metadata. This is a citation/availability check, not validation of the papers' scientific claims.

At the final capture,27 links returned HTML titles consistent with the intended work and two returned PDF headers(Chisel and Hyperband). Direct HTTP retrieval remained unresolved for the Lakens publisher DOI(403), TrainCheck's USENIX landing page(403) and the OffMate author-team report(network/TLS retrieval error). Those results do not establish dead links. Previously opened primary browser sources, the recorded read depths and independently retrievable publisher metadata remain distinct evidence; no access restriction was bypassed.

The old Capuchin author-hosted PDF could not be fetched in the direct audit. Its note now uses the available first-party Microsoft overview and publisher DOI. That overview spells the first author's given name “Quan”, while the publisher-deposited record says “Xuan”. The note retains Xuan following the [publisher metadata capture](publisher-metadata-audit.json). This is an actual metadata disagreement, illustrating why one source/title check is insufficient. Some automatically decoded HTML author fields contain replacement characters; those fields are not used to override the manually verified paper names.

Selected Crossref records verify publisher-deposited title/subtitle, authors, venue/date/pages for Capuchin, Lakens's primer and the confidence-sequence paper. Crossref's title field may contain only the short title, with the rest in a subtitle field; a naive exact-string title comparison would incorrectly flag those records. The capture is not a complete DOI audit of every cited work.

Version distinctions retained in notes include Adacc v1/v2 title changes, the two-author TensorFuzz preprint rather than a different publication version, Hyperband's preprint/publication years, EasyScale's revised title/venue, and the confidence-sequence preprint/journal/revision dates. Recent preprints remain labeled as such. No machine check establishes absence of related work, independent review, theorem validity, or current software compatibility.

A later [selected TrainCheck PDF audit](papers/traincheck-deeper-read.json) successfully retrieves the official PDF even though the earlier direct landing-page request failed. Historical failures remain unchanged. The new read has an exact byte identity and selected text/visual scope; neither a failed landing-page fetch nor a successful PDF fetch establishes implementation behavior. An OffMate public metadata request still failed certificate validation, with no bypass.
