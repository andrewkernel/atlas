# Frozen token-objective/reference adequacy control

Two original float64 CPU adapters share the same tiny embedding/linear model, fixed four-sequence input, seed 2301 and SGD/momentum update. Intended objective is the mean over all ten valid target tokens; individual sequence counts are 4, 2, 1 and 3. No dropout, BatchNorm, token dataset, pretrained weights or attention implementation is involved.

TokenCase correctly supplies summed valid-token cross entropy and token denominator. SequenceMeanCase deliberately averages each sequence's token mean before averaging sequences, while retaining the same stated token-weighted intent. Each adapter is supplied unchanged to all three workers of the existing pinned TrainParity accumulation checker with two sequence microbatches and explicit accounting. Predicted checker result is PASS for both because each candidate is compared to its own supplied reference objective. This tests a shared-reference limitation, not a checker bug or new detection benchmark.

Independently evaluate each adapter gradient/loss against an authored full-batch log-softmax/gather token oracle, using identical initial parameters. Predict near-rounding agreement for TokenCase and a finite mismatch for SequenceMeanCase. Preserve exact observed errors, validity-token counts and all checker reports; do not tune tolerance after execution. Checker tolerance is rtol 1e-10 / atol 1e-12 under its existing tensor/scalar conventions, not the proposed Atlas relation. The oracle observation does not become a general scientific-conclusion label.

Use the existing reviewed source revision and separate compatible CPU checker environment; verify every reviewed foreign source hash before import. Only the two authored allowlisted classes execute. Give explicit minimal environments, owned scratch/profile paths, 30-second nested worker limits and 115-second outer limits. Preserve every intended case and launcher error. Neither independent reviewers nor held-out cases are introduced. No upstream issue/message, application expansion, learned-checker run or new model data is authorized by this control.
