# Frozen shared-stack existing-tool integration

Use pinned reviewed TrainParity and Rockmate/rkgb source together in a separate Python 3.11.17/PyTorch 2.13.0+cu130/NumPy 2.4.6 environment. This satisfies the checker's declared Python/Torch bounds and the planner's metadata. The official CUDA wheel identity and all resolved dependencies are captured before execution. No source/build hook/C extension or new model/data download is introduced.

Three fixed modes, seed 2001, rtol=1e-5/atol=1e-7:

1. TrainParity accumulation runner on a native pure model, full logical batch 256 versus two 128-example forwards with explicit denominator. This is a positive GPU support/control.
2. The same runner with a reviewed conditional adapter: full-256 reference uses the original pure model; each 128-example candidate call uses its compiled 32 MiB Rotor wrapper. Scientific parameters are registered once and named identically within each check. All three worker builds prepare the same wrapper with a scoped RNG guard, so preparation is not silently different between arms. The runner still chooses its actual deferred-forward/backward schedule. Record its result without assuming it reproduces the 2.14 failure.
3. A competent adapted baseline uses the existing snapshot capture/comparison primitives around an authored streaming executor on the same conditional case. Compare initialized and post-update named parameters/gradients/SGD momentum, explicit denominator and normalized loss. The objective is pure/separable with metadata-known denominator; this is not a generic streaming conversion. Post-state RNG is deliberately excluded and disclosed. Inject a .01 change into one parameter after the valid comparison as a negative capture/comparison control.

The original four-block Linear/ReLU network and [256,64,64] logical input/target dimensions remain small finite diagnostics. One SGD update with lr .01/momentum .9, full FP32 legacy-only backend settings, no clipping/normalization/dropout/scheduler. The baseline case declares actual observed state, not a universal scientific relation. Numerical agreement is empirical under the frozen tolerance; no margin/seed tuning after outcomes.

Every subprocess has an explicit minimal environment and owned scratch directory. Each runner worker is bounded to 30 seconds, each outer mode to 120 seconds. Reports retain errors, abstentions, incomplete captures and nonfinite-field locations; no skipped outcomes are counted as pass. Source hashes are verified before importing reviewed references. This is trusted authored-code execution, not adversarial containment or a performance/energy benchmark. Existing capture reuse is deliberately included so a scheduling incompatibility cannot be misrepresented as proof Atlas needs a new generic checker. No primary independently labeled policy study or historical paper-suite replication is conducted here.
