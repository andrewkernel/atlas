# Frozen reusable-module and accumulation control

This exploratory study tests a concrete integration uncertainty exposed by the full HiRemate paper's Appendix C.2.2 (PDF page 20): reusable Autograd-compatible modules can have multiple forwards before backward. The current pinned family's serial pure controls do not test that relation. The inspected TrainParity accumulation worker also computes all microbatch losses before backward. Do not assume these components compose because each has passed a narrower fixture.

Use the already reviewed pinned source, explicit minimal environment, physical RTX 3060 and same original four-block Linear/ReLU network. Compile a named-x wrapper through generated Rotor configuration, sequence/base partitioning, Python solver, nominal 32 MiB planning budget, external SGD lr .01/momentum .9, no internal optimizer/offload. The tighter budget previously produced a static schedule with repeated forwards. No new third-party code or source patch is introduced.

Seed 1901 initializes each fresh trial. Create two different fixed [128,64,64] inputs and targets. Each loss is its squared-residual sum divided by the total element count of both microbatches. The main reference computes both native forward losses and backpropagates their sum, then performs one optimizer update. The native streaming positive computes/backpropagates each correctly normalized term before the next forward. Both share the same intended separable logical objective. Use no dropout, BatchNorm, mixed precision, clipping or scheduler.

Five fixed trial modes: native streaming; planner streaming; planner deferred forwards followed by separate backwards (matching the checker pattern); planner deferred forwards followed by joint backward; and planner single-forward positive (a separately identified one-microbatch objective/reference). The two positives are expected to match. Other modes test unresolved reusable/accumulation semantics rather than carrying presupposed unsafe labels. Any error, missing/None gradient, no schedule, nonfinite value or failed initialization replay remains visible. Do not tune tolerances after results.

Observe first loss, keyed gradients before the single optimizer step, post-step parameters and momentum. Predeclare elementwise rtol=1e-5/atol=1e-7 and additionally report global gradient relative-L2 error with explicit zero-reference handling. Numerical controls are not scientific equivalence margins. Construct the planner under the previously tested scoped Torch global RNG guard, restore initial parameter values, and clear gradients before the logical window. It does not certify custom state, other generators or mutable models.

Every mode runs in a fresh worker with a 60-second bound. Inputs are authored tensors, no external checkpoint or downloaded workload. This is a narrow compatibility/control experiment on the contemporary pinned source and stack, not replication of the paper's historical environment, independent expert labeling, field defect prevalence, an Atlas policy comparison or proof of an emergent failure of two universally valid transformations. Preserve baseline self-consistency and all outcomes before deciding whether an observation is an API limitation, adapter mistake, configuration error or implementation discrepancy.
