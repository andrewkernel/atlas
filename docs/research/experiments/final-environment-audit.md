# Post-experiment environment consistency audit

The [read-only inventory](final-environment-inventory.json) and [source](../../../benchmarks/snapshot_final_environments.py) examine six separate research environments without importing any ML package. Metadata identifies installed distribution versions. Thirty selected Torch Python files across the core/original-CUDA/checker/planner/interop environments, plus the NVML binding, match their installed wheel RECORD hashes. Earlier recorded CUDA/checker/planner/interop package versions have no mismatches after canonical name comparison. These are selected current consistency checks, not whole-package integrity, trusted signatures, contemporaneous attestation or scientific-correctness validation.

The first investigator comparison omitted period normalization and falsely treated ruamel.yaml and ruamel-yaml as different distributions. That [attempted inventory](final-environment-name-attempt.json) remains with its disposition. The corrected scanner follows [official packaging name normalization](https://packaging.python.org/en/latest/specifications/name-normalization/). No package change or disappearance is inferred from the false comparison.

Requirements/lock byte hashes and canonical JSON hashes of earlier records bind the inventory to portable committed identities. Telemetry requirements were normalized to LF before final hashing; package installation is unchanged. The NVML wrapper source matches the earlier observed availability identity. No model/data, environment variables, credentials or user-profile paths are captured. The original environments and research fixtures remain separate from the core CPU lock.

Cross-platform amendment: Linux CI run 38705602573 detected that the newly byte-hashed core uv.lock had platform-dependent checkout line endings. The lock now has an explicit LF attribute, and the inventory is recaptured after newline normalization. The lock dependency content and installed packages are unchanged. Earlier validation/hash captures remain historical; a local pass alone did not expose this issue.
