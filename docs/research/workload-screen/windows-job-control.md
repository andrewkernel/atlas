# Windows job lifecycle: retained failure and repaired launch order

The [initial attempt](windows-job-initial-attempt.json) fails with WinError 5. A [phase-only rerun](windows-job-phase-attempt.json) identifies assignment of the already-created actual interpreter as the failing phase; assignment of the launcher succeeds. Both clean up retained owned identities and stop. The precise existing job hierarchy/cause was not measured, so no OS defect or required elevation is inferred.

The prospective [protocol amendment](windows-job-protocol.md), frozen at 3772c01, starts the launcher suspended, verifies creation identity, assigns it to a new empty job and resumes its sole verified thread. The actual interpreter inherits group membership. This ordinary-permission sequence succeeds in all three intended [lifecycle cases](windows-job-control.json): natural exit, explicit group termination and closing the last job handle. Wrong creation identity and use after close are rejected. Both observed identities are gone before the next case. The [two platform-specific tests](../../../tests/test_windows_job_scope.py) exercise termination/close using the current interpreter and skip explicitly on other operating systems.

The 64 MiB touched allocation appears in actual-interpreter RSS around 86.8 MB, with the launcher around 4.75 MB. Job peak commit is around 79.3 MB. These measures have different scopes; no hard memory quota is set. Closing the group handle yields launcher exit code zero in the observed case even though it intentionally terminates the waiting child. Exit code zero alone is therefore not a scientific-completion signal: the supervisor's cancellation reason, complete worker payload and update counters must agree.

This is trusted local lifecycle infrastructure, not a sandbox or every-failure-path guarantee. The historical QA resource supervisor stays unchanged and defective. A separate [owned-worker supervisor](../../../benchmarks/qa_owned_worker.py) reuses the tested pre-execution group boundary for newly frozen authored diagnostics, checks actual-worker memory and job commit, retains partial records and verifies cleanup. The subsequent [BERT capture study](qa-numerical-control.md) supplies a real training use of that boundary, with its own guards and recorded scope.
